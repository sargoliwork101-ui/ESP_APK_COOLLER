# 🚀 پروژه کولر هوشمند ESP32 + نرم‌افزار اندرویدی (Local WebView / Capacitor App)

این پروژه، نسخهٔ بهینه‌سازی‌شده و تفکیک‌شدهٔ سیستم کنترل کولر با برد **ESP32-WROOM** است. در این نسخه، **تمام منطق عملکردی (سناریوها، تایمرها، رمزنگاری AES، محافظت کمپرسور، اتصال NTP و واچ‌داگ)** و همچنین **ظاهر و پالت رنگی پنل (رابط کاربری Vazirmatn، طرح گالری)** دقیقاً و **بدون ۱٪ تغییر** حفظ شده است. 

تغییر اصلی و کلیدی در معماری سیستم است:
1. **حذف بار سنگین نمایش (HTML/CSS/JS) از روی برد ESP32**: فایل حجیم ۶۷ کیلوبایتی `webpage.h` از روی کد برد حذف شده است. برد دیگر وقت، رم و حافظه فلش خود را صرف تولید و ارسال کدهای رشته‌ای HTML برای هر درخواست مرورگر نمی‌کند. در نتیجه، فشار پردازشی روی برد به حداقل رسیده و پایداری و سرعت پاسخ‌دهی آن چندین برابر شده است.
2. **انتقال کامل نمایش به نرم‌افزار اندرویدی (Capacitor App)**: کل رابط کاربری (تمام تب‌ها، کارت‌های سناریو، فرم‌های تنظیمات و انیمیشن‌های گرافیکی) اکنون به‌صورت محلی (Local) درون گوشی شما اجرا می‌شود و با برد از طریق **API های سبک JSON** در ارتباط است.

## ⚠️ نسخه هماهنگ فعلی (اجباری)

نسخه اندروید **کولر NVS V2.3** فقط باید همراه فریمور **API v3** همین شاخه استفاده شود. فایل صحیح برد:

```text
ESP32_Firmware/Cooler_ESP32_API_Server/Cooler_ESP32_API_Server.ino
```

فایل‌های پوشه `sample/` نسخه مرجع قدیمی‌اند و نباید روی برد آپلود شوند. در API v3 سناریوها، تنظیمات وای‌فای، محافظ کمپرسور و حالت دستی در **NVS داخلی ESP32** ذخیره می‌شوند؛ بنابراین به پارتیشن LittleFS وابسته نیستند و پس از خاموش/روشن شدن باقی می‌مانند. برنامه نیز قبل از ارسال هر فرمان ذخیره، نسخه فریمور و backend ذخیره‌سازی را کنترل می‌کند.

## 🛠 ۱. نحوه راه‌اندازی و آپلود کد روی برد ESP32

1. نرم‌افزار **Arduino IDE** را باز کنید.
2. فایل `Cooler_ESP32_API_Server.ino` موجود در پوشهٔ `ESP32_Firmware/Cooler_ESP32_API_Server/` را باز کنید.
3. مطمئن شوید کتابخانه‌های زیر در آردوینو نصب هستند (اکثراً همراه با پکیج ESP32 نصب هستند):
   - `WiFi.h`, `WebServer.h`, `LittleFS.h`, `time.h`, `esp_task_wdt.h`
   - کتابخانه `ArduinoJson` (نسخه 6 یا 7) از طریق Library Manager آردوینو.
4. برد خود را روی `ESP32 Dev Module` (یا مدل دقیق ESP32-WROOM خود) تنظیم کرده و کد را آپلود کنید.
5. پس از آپلود، برد شبکه وای‌فای با نام پیش‌فرض `ESP32_Timer_Hub` و گذرواژه `12345678` ایجاد می‌کند.

## 📱 ۲. نحوه دریافت خروجی نرم‌افزار اندروید (APK) با استفاده از GitHub

کد این پروژه طوری پیکربندی شده است که به محض قرار دادن آن روی گیت‌هاب (GitHub)، خروجی اپلیکیشن اندروید به صورت خودکار ساخته می‌شود:

### روش اول: بیلد خودکار با GitHub Actions (پیشنهادی و بدون نیاز به کامپیوتر قدرتمند)
1. یک مخزن (Repository) جدید در گیت‌هاب خود بسازید.
2. محتویات همین پوشه (فایل‌های پروژه از جمله `.github/workflows/build-android.yml`) را روی مخزن خود آپلود یا Push کنید.
3. در صفحه مخزن گیت‌هاب خود، به تب **Actions** بروید.
4. مشاهده می‌کنید که ورک‌فلو `Build Android APK (Local WebView / Capacitor App)` به صورت خودکار اجرا شده است.
5. پس از اتمام ساخت (حدود ۳ تا ۵ دقیقه)، در قسمت **Artifacts** همان صفحه، فایل‌های `Smart-Cooler-ESP32-App-Debug.zip` یا `Release` را دانلود کنید؛ داخل آن فایل `app-debug.apk` آماده نصب روی گوشی اندرویدی شماست!

### روش دوم: بیلد محلی روی کامپیوتر خودتان
اگر Node.js و Android Studio روی سیستم شما نصب است، دستورات زیر را در ترمینال اجرا کنید:
```bash
cd Android_App
npm install
npx cap sync android
cd android
./gradlew assembleDebug
```
فایل خروجی APK در مسیر زیر ساخته می‌شود:
`Android_App/android/app/build/outputs/apk/debug/app-debug.apk`

## 🔗 ۳. نحوه ارتباط اپلیکیشن موبایل با برد ESP32

- **در حالت اتصال مستقیم (پیش‌فرض)**: به محض اینکه وای‌فای گوشی خود را به شبکه `ESP32_Timer_Hub` وصل کنید و اپلیکیشن را باز کنید، برنامه به‌صورت خودکار با آدرس IP پیش‌فرض `http://192.168.4.1` با برد ارتباط برقرار می‌کند و تمام سناریوها و وضعیت رله را در کسری از ثانیه روی صفحه نمایش می‌دهد.
- **در حالت اتصال به مودم اینترنت خانه (STA)**: اگر برد و گوشی هر دو به وای‌فای مودم خانه وصل هستند، در بالای اپلیکیشن (یا در تب تنظیمات) روی گزینه **[تغییر آدرس IP]** کلیک کنید و آدرس IP برد در شبکه مودم (مثلاً `192.168.1.50`) را وارد کنید. برنامه این آدرس را در حافظه گوشی ذخیره می‌کند و همیشه با همان آدرس به برد متصل می‌شود.

## 🌟 ویژگی‌های برجسته نسخه جدید
- **کاهش چشمگیر مصرف RAM و Flash در ESP32**: با حذف رشته‌های طولانی HTML از کد C++، حافظه آزاد برد افزایش یافته و احتمال کرش یا کمبود حافظه به صفر رسیده است.
- **پشتیبانی کامل از CORS و Preflight**: تمام مسیرهای سرور ESP32 هدرهای استاندارد `Access-Control-Allow-Origin: *` و درخواست‌های `OPTIONS` را پشتیبانی می‌کنند تا موتور مرورگر اندروید هیچ مانع امنیتی برای ارتباط با برد ایجاد نکند.
- **همگام‌سازی لحظه‌ای سناریوها**: اپلیکیشن به محض اتصال، لیست ۲۰ سناریو ذخیره‌شده در فلش برد را از طریق API جدید `GET /scenarios` دریافت کرده و کارت‌ها را به دقت پر می‌کند.
