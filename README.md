# کولر هوشمند ESP32 — اپ اندروید (Local WebView)

این پروژه **ظاهر و منطق دقیق** پنل تحت‌وب اصلی را از روی ESP32 برمی‌دارد و داخل یک
اپ اندروید (Native WebView) اجرا می‌کند. ESP32 فقط داده را با یک REST/JSON API
سبک می‌فرستد/می‌گیرد، دیگر HTML سنگین سرو نمی‌کند (حجم فلش/رم خالی ESP32 بسیار
بیشتر می‌شود و پایداری بالاتر می‌رود).

```
CoolerApp/
├── esp32_firmware/        # فیرم‌ویر سبک جدید ESP32 (فقط API)
│   └── Cooler_ESP32_LightAPI.ino
├── web/                   # فایل‌های HTML/CSS/JS پنل (داخل assets اپ قرار می‌گیرند)
│   ├── index.html
│   └── app.js
└── android/               # پروژه‌ی اندروید استودیو (Native WebView)
    ├── build.gradle
    ├── settings.gradle
    ├── gradle.properties
    └── app/
        ├── build.gradle
        └── src/main/
            ├── AndroidManifest.xml
            ├── assets/web/  (کپی از web/ توسط شما یا Gradle)
            ├── java/ir/cooler/smart/
            │   ├── MainActivity.java
            │   └── AndroidBridge.java
            └── res/...
```

---

## گام ۱: فلش فیرم‌ویر سبک جدید روی ESP32

1. در Arduino IDE ، کتابخانه‌های زیر را نصب کنید (همان‌های قبلی):
   * `WiFi` (داخلی ESP32)
   * `WebServer` (داخلی ESP32)
   * `LittleFS_esp32` (معمولاً با هسته ESP32 می‌آید)
   * `ArduinoJson` نسخه ۶.x
2. فایل `esp32_firmware/Cooler_ESP32_LightAPI.ino` را باز کنید و برد `ESP32 WROOM Dev Module` را انتخاب کرده و روی برد فلش کنید.
3. تمام تنظیمات قبلی شما (سناریوها، وای‌فای، محافظت، ...) که در LittleFS ذخیره شده‌اند با فیرم‌ویر جدید هم سازگار هستند و حفظ می‌شوند.
4. بعد از فلش، اگر با مرورگر به IP برد بروید، به‌جای پنل کامل یک صفحه کوتاه راهنما می‌بینید.

> **مهم:** این فیرم‌ویر همچنان با نسخه‌ی قدیمی وب کاملاً سازگار است (endpointهای
> قبلی `/status`, `/sync`, `/toggle-manual`, `/save-ap`, `/save-sta`,
> `/save-ap-cycle`, `/save-protection`, `/save` همگی باقی مانده‌اند و CORS هم
> فعال شده). یعنی در صورت نیاز می‌توانید همزمان از مرورگر هم استفاده کنید — فقط
> دیگر HTML سنگین از طرف ESP سرو نمی‌شود و اپ گوشی از فایل‌های محلی استفاده می‌کند.

## گام ۲: خروجی APK از پروژه اندروید

### روش الف – ساده‌ترین: Android Studio
1. پوشه‌ی `android/` را با Android Studio باز کنید.
2. صبر کنید Gradle Sync تمام شود (اینترنت لازم است برای دانلود وابستگی‌ها).
3. از منوی **Build → Build Bundle(s) / APK(s) → Build APK(s)** استفاده کنید.
4. APK خروجی در `app/build/outputs/apk/debug/app-debug.apk` ساخته می‌شود.
5. (اختیاری) برای APK انتشار (Release) با امضای خودتان، از **Build → Generate Signed Bundle/APK** استفاده کنید.

### روش ب – خط فرمان (بدون Android Studio)
* روی لینوکس/مک: `./build.sh`
* روی ویندوز: `build.bat`
* یا دستی:
```bash
cd android
# نیاز است قبلاً JDK 11 و Android SDK (با ساپورت اندروید 34) نصب باشند.
# اگر gradle wrapper ندارید، اول از داخل Android Studio یکبار پروژه را باز کنید
# (یا روی سیستمی که gradle نصب است، دستور `gradle wrapper --gradle-version 8.4` بزنید).
./gradlew assembleDebug
# خروجی: app/build/outputs/apk/debug/app-debug.apk
```
> نکته: فایل‌های فونت Vazirmatn (woff2) و `manifest.json` همگی داخل `web/` قرار دارند
> و تسک Gradle به نام `copyWebAssets` قبل از هر بیلد به‌طور خودکار آن‌ها را به
> `android/app/src/main/assets/web/` کپی می‌کند. پس برای به‌روزرسانی UI کافی است فایل‌های
> درون `web/` را ویرایش کنید و APK بگیرید — نیازی به کپی دستی نیست.

> قبل از بیلد، فایل‌های `web/index.html` و `web/app.js` در پوشه‌ی
> `android/app/src/main/assets/web/` قرار می‌گیرند — در این ریپو از قبل کپی شده‌اند.
> اگر فایل وب را تغییر دادید، فقط کافی است دوباره آن را در `assets/web/` کپی کنید.

## گام ۳: نصب و استفاده

1. APK روی گوشی را نصب کنید (اجازه‌ی نصب از منابع ناشناس بدهید).
2. گوشی را به وای‌فای خود برد (AP پیش‌فرض `ESP32_Timer_Hub` / رمز `12345678`) وصل کنید **یا** هر دو گوشی و برد را به یک مودم وصل کنید.
3. اپ را باز کنید. پیش‌فرض به IP استاندارد ESP32 در حالت AP یعنی `192.168.4.1` متصل می‌شود.
4. اگر با LAN مودم کار می‌کنید، از پنل «خانه → تنظیمات اتصال به برد» IP محلی برد را وارد کنید.
5. ظاهر و کارکرد پنل دقیقاً مثل نسخه‌ی مرورگر است — تفاوتی احساس نخواهید کرد.

## APIهای فعال روی ESP32

| Method | Endpoint           | کاربرد                                         |
|--------|--------------------|-------------------------------------------------|
| GET    | `/`                | صفحه کوتاه راهنما (برای مرورگر)                 |
| GET    | `/status`          | وضعیت زنده (همان JSON قبلی، چند فیلد اضافه)    |
| GET    | `/config`          | تنظیمات فعلی (برای پر کردن خودکار فرم در اپ)   |
| GET    | `/scenarios`       | لیست سناریوهای فعال                            |
| POST   | `/toggle-manual`   | تغییر حالت دستی                                |
| POST   | `/sync`            | همگام‌سازی ساعت                                |
| POST   | `/save`            | ذخیره سناریوها (بدنه JSON)                    |
| POST   | `/save-ap`         | ذخیره SSID/رمز AP                              |
| POST   | `/save-sta`        | ذخیره تنظیمات STA                              |
| POST   | `/save-ap-cycle`   | ذخیره چرخه AP و قدرت سیگنال                   |
| POST   | `/save-protection` | ذخیره محافظت کمپرسور                           |

همه‌ی پاسخ‌ها هدر `Access-Control-Allow-Origin: *` دارند.

## چند نکته

* **پل بومی `AndroidBridge`** درون `MainActivity.java` تمام درخواست‌های HTTP را
  از سمت اندروید (نه از داخل WebView) ارسال می‌کند، یعنی:
  - مشکل **CORS** اصلاً پیش نمی‌آید.
  - مشکل **cleartext HTTP** در اندروید ۹+ به‌صورت مطمئن رفع شده.
  - می‌توانید Timeout را دقیق کنترل کنید.
* **فونت Vazirmatn** به‌صورت محلی داخل `assets/web/fonts/` باندل شده و با `@font-face`
  لود می‌شود. یعنی حتی وقتی گوشی فقط به AP برد (بدون اینترنت) وصل است، فونت دقیقاً مثل
  نسخه‌ی مرورگر نمایش داده می‌شود و ظاهر تغییری نمی‌کند (حدود ۲۵۰KB از حجم APK).
* **سازگاری با PWA**: اگر بعداً خواستید به‌جای اپ اندروید از PWA استفاده کنید،
  می‌توانید همین فایل‌های `web/` را روی هر استتیک هاست (مثلاً GitHub Pages) قرار
  دهید — چون برد CORS را فعال کرده، PWA هم بدون هیچ تغییری کار می‌کند.
* **اندازه فیرم‌ویر**: حذف HTML (قریب به ۷۰KB از فلش) و همه کمکی‌های ارسال HTML
  به‌صورت تکه‌تکه، حافظه فلش و heap قابل‌توجهی آزاد می‌کند و پایداری ارتباط را
  بالاتر می‌برد.

اگر به هر دلیلی خواستید برگردید، کافیست فیرم‌ویر اصلی قبلی خود (که HTML را سرو

## حالت PWA (بدون نیاز به اپ اندروید)

فایل‌های داخل `web/` استندالون هستند و می‌توانید آن‌ها را روی هر هاست استاتیک (مثل
GitHub Pages، Netlify، Cloudflare Pages یا حتی `python -m http.server` روی شبکه
محلی) قرار دهید تا به‌صورت PWA از مرورگر گوشی استفاده کنید. فقط باید:

1. آدرس IP برد را از بخش «تنظیمات اتصال به برد» در اپ وارد کنید.
2. مطمئن شوید برد و گوشی هم‌بندی به یک شبکه (AP خود برد یا LAN مودم) وصل هستند.
3. (اختیاری) برای نصب به‌عنوان اپ موبایل از دکمه‌ی «Add to Home Screen» در مرورگر
   استفاده کنید — `manifest.json` آماده شده است.
